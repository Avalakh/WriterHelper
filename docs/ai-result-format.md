# Работа ИИ по структуре и формат результата

Для глобальной задачи автор выбирает целью проект или книгу. Сначала модель получает карту всей структуры проекта: ID, тип, родитель, заголовок, путь, номер, размер текста, названия полей с признаками заполненности и короткий список обозначений персонажа. Тексты и значения полей в карту не входят. Карта при необходимости отправляется несколькими страницами.

Модель возвращает `sourceIds` (основания), `inspectTargetIds` (конкретные цели, текущие данные которых нужны) и `reason`. При дозаполнении персонажей ей достаточно выбрать сюжет/канон и видеть краткий список карточек. Прочитать существующее описание можно отдельным запросом через `inspectTargetIds`. Для поиска программа дополнительно гарантирует чтение всей выбранной иерархии, чтобы упоминания не зависели от выбора модели.

Основания и явно запрошенные карточки делятся на фрагменты с `id`, `field`, `start`, `end`, `totalLength`, `text`. Каждый вызов проверяется по консервативной оценке размера сообщения плюс лимиту ответа. Для поиска и проверки полный краткий список целей передаётся сразу, а каждое выбранное основание читается один раз. Для работы с несколькими группами материалов основания сначала превращаются в короткие адресованные выдержки; последующие проходы используют эти выдержки, а не снова весь текст. Модель выбирает минимальный набор и при необходимости дополнительно сокращает его, исключая дубли сюжет/план/сцены. Все замечания и предложения частей сохраняются; повторяющиеся предложения объединяются, а общий текст итога собирается моделью в несколько уровней. Противоречащие варианты остаются на выбор автора. До завершения задачи результат нельзя принять.

Ответ модели — JSON с полями `summary`, `findings`, `changes`. Кнопка «Скачать JSON» добавляет оболочку `format: writerhelper-ai-result`, `version: 1`, цель, операцию и список версий исходников. Пример:

```json
{
  "summary": "Предлагается усилить эмоциональную реакцию героя и добавить новую главу.",
  "findings": [{"id": "manuscript-id", "quote": "Незнайка грустит.", "message": "Можно показать реакцию через действие."}],
  "changes": [
    {"id": "manuscript-id", "reason": "Показать эмоцию", "textEdits": [{"start": 0, "end": 8, "before": "Незнайка", "text": "Грустный Незнайка"}]},
    {"id": "character-id", "reason": "Дополнение из сюжета", "contentAppend": "Ищет друга."},
    {"key": "new-chapter", "parent": "plan-id", "type": "chapter", "title": "Продолжение", "number": 2, "reason": "Следующий этап сюжета"},
    {"key": "new-manuscript", "parent": "new-chapter", "type": "manuscript", "title": "Рукопись", "content": "Новый текст.", "reason": "Текст предложенной главы"}
  ]
}
```

`id` обновляет существующий материал. `fields` содержит только изменяемые поля. `contentAppend` дополняет текст без переписывания непрочитанного оригинала. `textEdits` заменяет точные диапазоны исходного текста; координаты считаются в единицах UTF-16, как позиции JavaScript/редактора. `content` заменяет текст целиком и разрешён в рабочем вызове только для пустой цели или полностью прочитанного оригинала.

Новый материал указывает `key`, `parent`, `type`, `title`, при необходимости `content`, `fields`, `number`. Родителем может быть существующий узел выбранной области или `key` нового узла того же предложения. Программа назначает постоянные UUID только при принятии. Книга и глава требуют номера, сцена — полного набора обязательных полей. Для перемещения и переименования существующего материала используются `id`, `parent`, `title`, `reason`.

Допустимые связи соответствуют структуре приложения: проект → книги, канон, персонажи; книга → стиль, мир, сюжет, поглавный план, предпросмотр, источники; поглавный план → главы; глава → сцены, рукопись; сцены → сцены-планы; персонажи → персонаж → особенности; мир → правила; канон → источники.

Автор видит «Было / Будет», место назначения и новые ветки, выбирает изменения, затем принимает их одной транзакцией. Дочерний новый узел нельзя принять без его нового родителя. Правки за пределами цели, циклы, несовместимые изменения и устаревшие исходники блокируются. Поиск и проверка возвращают только отчёт. При сбое или отмене незавершённый результат не применяется.

Экономия: обычный вход одного вызова ограничен консервативной оценкой 32768 токенов или доступным контекстом меньшей модели. Заголовки передаются таблицей с короткими ID; одинаковые content и поля не дублируются. Неизменившиеся запросы кэшируются в памяти на 15 минут (до 96 записей); ключ зависит от подключения, модели и точных сообщений. Некорректные результаты не переиспользуются. В «Как выбран контекст» видны вызовы, попадания в кэш и оценки входящих/исходящих токенов; это не фактический биллинг провайдера.

Ошибочный JSON или цитата исправляются одним коротким дополнительным вызовом. Различия только в пробельных символах сверяются с точным оригиналом локально. Неподтверждённые замечания после неудачного исправления сохраняются отдельно; отчёт помечается неполным, проверенные выводы остальных частей остаются. Непроверенные изменения текста не применяются.
