# JSON-импорт WriterHelper, версия 1

Выберите в приложении **Импорт JSON** и одновременно загрузите `project.json` и все файлы книг, перечисленные в `project.books`. Либо выберите **Загрузить из каталога** и укажите каталог с тем же `project.json` и указанными файлами книг. Каталог использует собственный формат WriterHelper; карты старых проектов и их Markdown-каталоги не разбираются приложением. Файлы кодируются в UTF-8. Формат предназначен для других книг и для повторного импорта: исходный каталог и абсолютные пути не требуются. Пример минимального пакета приведён ниже.

## `project.json`

```json
{
  "format": "writerhelper-project",
  "version": 1,
  "project": {
    "id": "my-novel",
    "title": "Мой роман",
    "canon": { "id": "my-novel-canon", "title": "Канон (Лор)", "sources": [] },
    "characters": {
      "id": "my-novel-characters",
      "title": "Персонажи",
      "items": [
        {
          "id": "hero", "title": "Герой", "content": "Подтверждённое описание.",
          "fields": { "role": "Исследователь", "aliases": ["Незнакомец"] },
          "aspects": []
        }
      ]
    },
    "books": [{ "file": "book-1.json", "id": "my-novel-book-1", "number": 1, "title": "Книга 1" }]
  }
}
```

Один элемент `characters.items` соответствует одной личности. `fields.aliases` связывает обозначения из сцен с её карточкой; это **не означает**, что POV-персонаж знает её имя. Для скрытого имени можно задать `fields.concealedLabels: ["Незнакомец"]`: при генерации отдельной сцены пакет не выдаст истинное имя профиля. Сюжет сцены остаётся источником того, что конкретный герой знает в конкретный момент. `aspects` содержат особенности по книгам и времени: `fields.book` — ID книги, `from`/`until` — номера глав, `knowledge: "pov"` и `pov` ограничивают знание наблюдателя.

Элемент `canon.sources` или `book.sources` — обычный материал с `id`, `title`, `content`, `fields`. Ссылка без подготовленного текста не заменяет `content` и блокирует обязательный источник при генерации.

## `book-N.json`

```json
{
  "format": "writerhelper-book",
  "version": 1,
  "projectId": "my-novel",
  "book": {
    "id": "my-novel-book-1", "number": 1, "title": "Книга 1",
    "style": { "id": "style-1", "title": "Стиль", "content": "Правила повествования.", "fields": {} },
    "world": { "id": "world-1", "title": "Описание мира", "content": "Правила места.", "fields": {} },
    "plot": { "id": "plot-1", "title": "Сюжет", "content": "## Глава 1. Начало\n...", "fields": {} },
    "plan": { "id": "plan-1", "title": "Поглавный план", "content": "Полный исходный план", "fields": {} },
    "preview": { "id": "preview-1", "title": "Предпросмотр", "content": "", "fields": { "font": "Georgia", "size": 17, "width": 700, "height": 990, "margin": 60, "heading": 26 } },
    "sources": [],
    "chapters": [{
      "id": "chapter-1", "number": 1, "title": "Начало", "content": "Подробный план главы", "fields": {},
      "scenes": [{
        "id": "scene-1", "number": 1, "title": "Сцена 1", "content": "Событие",
        "fields": { "номер": 1, "атмосфера": "Тихо", "сюжет": "Событие", "персонажи": ["Герой"], "дополнительные_детали": [] }
      }],
      "manuscript": { "id": "manuscript-1", "title": "Рукопись", "content": "Готовая проза главы", "fields": {} }
    }]
  }
}
```

`projectId`, ID книги и номер обязаны совпадать с записью в `project.json`. Все ID внутри набора уникальны и остаются постоянными при повторном импорте. У каждой книги должны быть пять разделов, массивы `sources` и `chapters`; у главы — массив `scenes` и объект `manuscript`, даже если текста пока нет. Номера глав положительные и уникальные в книге. У сцены обязательны числовой `number` и `fields.номер`, строки `атмосфера` и `сюжет`, массивы строк `персонажи` и `дополнительные_детали`. Остальные поля сцены сохраняются. `content` хранит полный текст без сокращения; текст рукописи не делится автоматически по сценам. Незапланированная глава может иметь пустые `content`, `scenes` и `manuscript.content`.

У каждого материала необязательное `provenance` может содержать `relative`, `sha256` исходного файла и `locator`. Эти сведения служат только историей происхождения. Импортёр сохраняет точные байты загруженного JSON и локальные снимки содержимого в собственном хранилище. SHA-256 локального снимка соответствует именно его байтам; контрольная сумма прежнего файла хранится отдельно как справка. Запуск и генерация не читают прежние пути. Ключи ИИ, кандидаты генерации и история чата в формат не входят.

Раздел `world` может содержать необязательный массив `rules`. Каждый элемент — материал с постоянным `id`, `title`, полным `content`, `fields` и необязательным `provenance`; при импорте он становится дочерним правилом мира. Поля `category`, `knowledge`, `location`, `from`, `until`, `pov`, `conflict` сохраняют область действия. Отсутствие `rules` в прежнем пакете поддерживается и не удаляет имеющиеся правила. Ограничения по месту, времени и знанию заполняются только при наличии основания в источнике.

Для формы стиля используйте `fields.pov`, `tense`, `language`, `dialogue`, `tempo`, `emotion`, `examples`, `limits`. Полный `content` сохраняется отдельно и не заменяет эти параметры. Сцена дополнительно поддерживает `fields.location`, `pov`, `time`; `time` обозначает время события, а не время повествования. Подготовка среза переносит точные фрагменты и записывает основания в отчёт; отсутствие рукописи, индивидуального POV или точной даты не заполняется выдуманным текстом.

## Проверка и повторный импорт

Кнопка **Проверить JSON** проверяет все файлы и показывает числа материалов и локальные конфликты без записи. Кнопка **Загрузить JSON-проект** пишет все материалы одной транзакцией. Повторная загрузка с теми же ID и текстом не создаёт копий. При одновременной локальной правке текста, полей, названия или порядка и изменении JSON нужно отдельно решить каждый конфликт: сохранить локальное или принять JSON. Отсутствующий в новом наборе материал не удаляется автоматически. Источники других проектов не затрагиваются.


## Пакет в каталоге и независимость

Все файлы лежат непосредственно в выбранном каталоге. Ссылки на книги имеют вид `book-N.json`; переходы `../`, абсолютные пути и ссылки через символический файл за пределы каталога запрещены. Отсутствующий файл, неподдерживаемая версия, повтор ID, чужой проект или повтор номера книги блокируют запись. Изменение файлов после просмотра состава требует новой проверки. Для импорта файлов и каталога действуют одинаковые ограничения и сохранение локальных правок.

Iron Mind входит в приложение исключительно как подготовленный JSON-срез. Отдельный инструмент `scripts/prepare-iron-json.js` преобразует действующие материалы старой книги в этот формат; приложение его не вызывает. После загрузки пакет и старый каталог можно переместить: действующий проект хранится в WriterHelper. Повторный импорт нового среза выполняется только по явному выбору автора.
