# WriterHelper

Локальное рабочее место для подготовки и написания книг. Первый загруженный проект — «Железный разум». Приложение хранит проект в `data/writer.sqlite`, точные снимки исходных файлов в `data/sources/`, а ключи API отдельно в `data/secrets.dpapi.json`, защищённые Windows DPAPI текущей учётной записи.

Ctrl+S выполняет действие кнопки сохранения в активном редакторе: материалы, предпросмотр, кандидаты, подключения ИИ, промпты и схемы. Работает в русской и английской раскладке. Открытый диалог блокирует сохранение редактора за ним. Проверка: `npm run test:save-shortcut`.

## Запуск на Windows

Двойной щелчок по **`WriterHelper.exe`** в папке проекта открывает отдельное окно программы. Закрытие крестиком и сворачивание прячут его в системный трей. Двойной щелчок по иконке трея возвращает окно; правой кнопкой открывается меню **«Открыть WriterHelper» / «Свернуть в трей» / «Выход»**. Повторный запуск EXE открывает уже работающий экземпляр.

Оболочка использует существующую папку `data`, встроенный Node.js из `.desktop/node.exe` и установленный Microsoft Edge WebView2 Runtime. Терминал для такого запуска не нужен. При выходе незавершённый ввод сохраняется в локальный черновик. Профиль окна хранится в `data/desktop-browser`; настройки и черновики обычного браузера остаются в его профиле, поэтому перед первым переходом в EXE сохраните текущий ввод в браузере.

Для каждой рукописи приложение автоматически запоминает место чтения: прокрутку страницы, прокрутку текстового поля и позицию курсора или выделение. При возвращении из другого раздела, переключении между рукописями и повторном открытии приложения восстанавливается оставленное место. Позиции хранятся в текущем профиле браузера или окна приложения. Проверка этого поведения: `npm run test:manuscript-position`.

В панели ИИ цель генерации всегда совпадает с материалом, выбранным в структуре. Путь цели содержит книгу и главу; для смены цели выберите другой пункт дерева или результат поиска. Список результатов показывает только кандидатов выбранного материала. Открытие кандидата не меняет цель панели. Для папок структуры генерация недоступна. Проверка: `npm run test:generation-target`.

EXE запускается из своей папки вместе с `server`, `dist`, `.desktop`, `desktop` и DLL WebView2; переносить один EXE отдельно не следует. Если сервер WriterHelper уже запущен с той же папкой данных, оболочка использует его; при выходе останавливает только сервер, который запустила сама.

Пересборка: `npm run build:desktop`. Сборщик использует C#-компилятор .NET Framework Windows и официальный SDK WebView2 версии `1.0.4258.31`; при отсутствии SDK скачивает эту фиксированную версию из NuGet. [Требования и распространение WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution).

Для запуска в браузере остаётся прежний способ:

Нужен Node.js 24 или новее. Из каталога `D:\Work\projects\WriterHelper`:

```powershell
npm ci
npm run build
npm start
```

Откройте `http://127.0.0.1:4317`. Разработка: `npm run dev`. Порт можно изменить переменной `PORT`, каталог данных — `WRITER_DATA`. Сервер слушает только loopback. Окно терминала должно оставаться запущенным. Проверка: `npm test` и `npm run test:ui` (для UI нужен установленный Edge). Изолированные тестовые базы и снимки экрана находятся в `test-data/` и `reports/screenshots/`.

## Независимые проекты и импорт

WriterHelper работает с любыми книжными проектами. «Железный разум» — первый набор данных, загруженный как самостоятельный срез. Запуск, редактирование, промпты, генерация и предпросмотр не читают каталог прежней книги и не отслеживают его изменения.

**Импорт JSON** принимает `project.json` и все перечисленные `book-N.json` собственного формата WriterHelper. **Загрузить из каталога** принимает каталог с теми же файлами, например `D:\Books\my-novel`; этот путь автор вводит сам. Оба способа показывают состав и конфликты до транзакционной записи. Произвольный старый каталог книги, `runs`, карта проекта или манифест навыка не являются форматом импорта. Перемещение пакета не требует старых абсолютных путей.

При повторном импорте нового явно выбранного пакета локальные изменения текста, полей, названия и порядка требуют решения при конфликте: сохранить локальную версию или принять JSON. Неизменившийся пакет сохраняет локальные правки. Существующие записи, отсутствующие в пакете, автоматически не удаляются. Импорт не выполняет синхронизацию или обратную запись.

Готовый срез «Железного разума» находится в `imports/iron-mind/`. Подготовка среза из старых действующих материалов выполняется отдельным инструментом и не входит в запуск приложения:

```powershell
npm run prepare:iron-json -- "D:\Work\projects\Книга Iron mind" "imports/iron-mind"
node scripts/verify-iron-snapshot.js "D:\Work\projects\Книга Iron mind"
```

Подготовитель читает старую структуру, формирует полные JSON-файлы и проверяет неизменность источников. Он не открывает рабочую базу приложения. Импорт готового пакета через консоль: `npm run import:json -- "КАТАЛОГ_JSON_ПАКЕТА"`; при локальных конфликтах используйте интерфейс для явного выбора.

Формат описан в [docs/json-import-format.md](docs/json-import-format.md). В пакет не включаются ключи ИИ, кандидаты и история чата. Общие промпты поставляются самим WriterHelper; правила конкретной книги живут в её данных.

## Существующие данные и история загрузки

При первом запуске обновлённой версии миграция создаёт согласованную резервную копию `data/writer.sqlite.before-2` и меняет только метаданные прежнего импорта. ID, тексты, поля, связи, порядок, задачи, пользовательские промпты, ревизии и история сохраняются. Повторно импортировать книгу для обновления программы не нужно. При ошибке миграции изменения базы откатываются.

Блок **Снимок на момент загрузки** открывает локальную копию из `data/sources/` и показывает SHA-256 именно её байтов. Старый путь, если сохранён, спрятан в справочных сведениях об импорте и не является рабочей связью. Генерация использует текущие материалы программы, а не снимок прежнего импорта.

## Проверки

Основные проверки не требуют каталога Iron Mind: `npm test`, `npm run test:ui`, `npm run test:json-ui`, `npm run test:preview`, `node tests/scene-layout.js`, `node tests/startup.js`, `node scripts/verify-books.js`. Доказательство ограничения доступа: `node --permission --allow-fs-read=. --allow-fs-write=. tests/independence.test.js`.

Отдельные проверки подготовки среза: `npm run test:preparation` и `node scripts/verify-iron-snapshot.js "КАТАЛОГ_СТАРОЙ_КНИГИ"`; только они используют старые источники. Проверка миграции на копии текущих данных: `node scripts/verify-data-migration.js`; рабочая база при этом не меняется. Текущие результаты — в `reports/independence-verification.md`.

## Рабочее место

Слева находятся Лор, таблица персонажей и книги. В книге: Стиль → Описание мира → Сюжет → Поглавный план → Предпросмотр. Под планом — главы; каждая глава владеет сценами плана и одной цельной рукописью. Список, карточки и хронология сцен показывают одни и те же записи. У сцены есть номер, атмосфера, сюжет, персонажи, дополнительные детали и необязательное название. Отсутствующий план не подменяется текстом рукописи. Полный исходный Markdown/JSON остаётся доступен в разделе плана и в снимке.

В лоре добавляются текст и ссылка на первоисточник с пояснением применимости и авторского отступления. Пока у ссылки нет подготовленного текста, генерация с ней блокируется. В мире правила имеют категорию, локацию, временной диапазон и режим знания. У персонажа есть единый профиль, алиасы и особенности по книгам или главам. Поздняя особенность с явным `from` не попадает в пакет ранней главы. Неясное важное состояние помечают как `unresolved`, чтобы сборка показала вопрос вместо догадки. Изменение основания помечает зависимые планы и рукописи для пересмотра.

В каждом выбранном материале есть задача для ИИ. Для контейнера сначала выбирают конкретную цель. «Посмотреть контекст» показывает сохранённый неизменяемый пакет: источники, роли, локаторы, версии, подставленные промпты и оценку бюджета. Пакет отправляется кнопкой «Сгенерировать». Кандидат можно сравнить, поправить, проверить, принять или отменить. Только «Принять» меняет действующий материал; прежние ревизии доступны через «Восстановить предыдущую версию». Для переработки диапазона укажите его точный текст. Проверка источников и читательская проверка являются отдельными промптами и отдельными запусками; «не выполнялась» и «не завершена» не считаются успехом.

## Подключение ИИ

«Настройки ИИ» поддерживают совместимый `/v1/chat/completions` HTTP API и список `/v1/models`, либо локальный исполнитель. Для Bonsai запустите `D:\Tools\llama\StartBonsai.cmd`, затем укажите `http://127.0.0.1:1234/v1` и выберите модель из списка. Команда импорта добавляет это подключение автоматически, если сервер и модель уже доступны. Ключ необязателен для локального Bonsai; при наличии ключа он остаётся в DPAPI, не входит в книгу и пакет. Укажите предел контекста, ответа и тайм-аут; оборванный запрос не повторяется автоматически. Из-за настроек `reasoning-effort` Bonsai даже короткий ответ может выполняться долго.

Локальный исполнитель — это **совместимая программа**, которую сервис запускает напрямую без оболочки. Она получает одну JSON-запись в stdin с `packet`, `messages`, `model`; отдаёт в stdout один объект `{"text":"..."}`. Дополнительная диагностика идёт в stderr. Путь к EXE и аргументы вводятся отдельно. `StartBonsai.cmd` является запускателем сервера; после него используется HTTP-вариант. Путь и аргументы исполнителя не предназначены для хранения секретов.

## Промпты и конструктор

Восемь исходных шаблонов обезличены и имеют ссылку на файл и SHA-256 источника. Общий шаблон действует в выбранной области; локальная копия имеет свой ID и ревизии. В библиотеке задаются текст, этап генерации/проверки, целевой тип, порядок, включённость, обязательные переменные и условия `book`, `from`, `until`. При равном порядке сортировка идёт по ID. Изменение общего шаблона затронет все схемы, где он применяется; создание локальной копии сохраняет исходный шаблон.

Конструктор соединяет источник или промпт с выбранной генерацией. Стрелки имеют роль: ограничение, события, стиль, участники, граница либо редактируемый текст. Можно подключить существующий материал, добавить внешний текст, создать промпт прямо на схеме, выбрать точный фрагмент и обязательность. Порядок промптов определяется числом, размещение узлов — только расположение на экране. Схемы наследуются от приложения, проекта и книги. Локальная схема хранит отличия; изменившаяся основа требует просмотра конфликта. Сброс показывает удаляемые локальные связи и оставляет тексты и библиотеку промптов. Связь с текущим текстом при переработке — входной снимок, остальные циклы блокируются.

По умолчанию канон/мир/персонажи ограничивают сюжет, сюжет назначает события плана главы, полный план сцен входит в рукопись, стиль действует отдельно на сюжет/план/прозу, а соседние главы обозначают границу. Предпросмотр показывает страницы только из действующих рукописей; список ненаписанных глав остаётся видимым. Настройки оформления могут пройти через тот же цикл кандидата. Сборка предпросмотра не изменяет исходные тексты и пока не экспортирует издательский файл. В верхней панели предпросмотра доступны размеры основного шрифта и заголовков, масштаб и ширина/высота полотна. Для новых книг размер по умолчанию — A4 в книжной ориентации: 210 × 297 мм (794 × 1123 CSS px). Кнопка «A4 · книжная» возвращает этот размер; «На всю ширину» заполняет свободную область с отступом 12 px, сохраняя книжные пропорции A4 210:297 за счёт соответствующей высоты. Сохранённые размеры существующих книг остаются прежними. Числа можно вводить с клавиатуры; Enter или уход из поля завершает ввод. Обычное колесо прокручивает страницы вверх и вниз, Ctrl + колесо меняет масштаб, Alt + колесо пропорционально меняет размеры полотна. Масштаб хранится отдельно в предпочтениях окна; оформление записывается в проект через «Сохранить». Для прокрутки также доступны полоса прокрутки и Page Up / Page Down.

## Выгрузка книги

В верхней панели находится отдельная кнопка **«Выгрузить книгу»**. Выберите TXT, FB2, EPUB, Markdown (.md), HTML, DOCX или PDF, при необходимости укажите автора и язык, затем нажмите **«Скачать файл»**. В Windows-оболочке откроется окно выбора имени и папки; в браузере файл сохранится через обычную загрузку.

Экспорт собирает сохранённые рукописи только выбранной книги в текущем порядке глав. Пустые главы пропускаются и перечисляются в окне выгрузки. Лор, планы, кандидаты, история и локальные черновики в файл не входят. Чтобы включить последние правки, сначала сохраните их. Если материалы изменились после открытия окна, откройте выгрузку заново.

Markdown сохраняет исходную разметку; остальные форматы передают текст, заголовки и границы сцен. HTML и EPUB содержат оглавление; EPUB, FB2 и DOCX сохраняют базовое выделение текста. Внешние изображения не скачиваются: сохраняется подпись. PDF использует установленный в Windows шрифт Georgia, Times New Roman или Arial с кириллицей. DOCX и PDF имеют самостоятельное книжное оформление. Предпросмотр и его настройки остаются без изменений.

Проверки экспорта: `node --test tests/book-export.test.js` и `node tests/book-export-ui.js`.

## Копии и восстановление

Перед обновлением приложения закройте сервер и скопируйте каталог `data/` целиком. База хранит журнал WAL; копируйте файлы вместе либо после остановки сервера. Перед миграцией создаётся `data/writer.sqlite.before-N`. Если миграция завершится ошибкой, транзакция возвращает действующую базу в прежнее состояние; для ручного восстановления остановите сервер, сохраните текущий `writer.sqlite`, затем скопируйте нужный `.before-N` поверх него. Снимки источников и `secrets.dpapi.json` храните вместе с копией; DPAPI-ключ переносится только в рамках той же учётной записи Windows. Проверяйте восстановление на отдельном `WRITER_DATA`, прежде чем заменять рабочую базу.

При переходе с несохранёнными правками доступны «Сохранить и перейти», «Оставить черновик», «Не сохранять» и «Остаться». «Не сохранять» отменяет правки и удаляет локальный черновик только текущего материала. В предпросмотре меняется оформление; текст правится в рукописях глав. Фокус полей, прокрутка, масштаб и изменение размера окна не считаются изменениями книги.

Защита несохранённых изменений действует также в настройках ИИ, промптах и конструкторе генерации. Результаты и сценарии проверки: [аудит разделов](docs/unsaved-changes-audit.md).

Кнопки работы с фрагментом находятся во вкладке «ИИ» боковой панели, в группе «Работа с фрагментом». В верхней панели рукописи эти кнопки не дублируются. Переработка выделения запускается здесь; общая операция «Переработать» относится ко всей рукописи. «Запрос по выделению» открывает окно произвольного вопроса, проверки или анализа: выберите ИИ, введите запрос, получите ответ в том же окне. Передаётся текущий выделенный текст, включая локальные правки; запрос не сохраняет и не заменяет рукопись и не создаёт кандидата. Для новой редакции с последующим принятием используйте «Перегенерировать выделенное».

Проверка оболочки с реальной кнопкой панели задач: `WriterHelper.exe --self-test --taskbar-self-test --data-dir <тестовая-папка> --port <свободный-порт> --report <отчёт.json>`. Проверяются крестик, сворачивание, восстановление, повторный запуск, неизменность окон WebView2 и сохранение состояния браузера. Рабочую папку `data` для этой проверки не используйте.

Инструменты фрагмента работают с активным текстовым полем во всех разделах с панелью ИИ: стиль, мир, сцены, планы, свойства, задача и редактор кандидата. Запрос доступен также для выделения в тексте только для чтения; замена и вставка требуют редактируемого поля. Результат для обычного поля проверяется в диалоге и применяется локально кнопкой «Применить к полю», после чего материал сохраняется обычным способом. Для рукописи остаётся отдельный кандидат с принятием. При переходе к другому материалу прежнее выделение сбрасывается.
Все три инструмента используют общий сборщик `buildFragmentContext` и общую подготовку сообщений `fragmentMessages`. В каждом окне есть «Передаваемый контекст» и выбор объёма. По умолчанию сохранён полный контекст; «Ближайший контекст» отбирает окружение (до 1600 знаков с каждой стороны), план ближайшей сцены, выдержки стиля, событий, участников и ограничений в пределах 16000 знаков и доступного бюджета. Выбор сцены для цельной рукописи без маркеров является оценкой по тексту и положению фрагмента. Полный режим рукописи использует настроенную схему источников с прежними фильтрами времени и POV.

Сравнение Bonsai: `node scripts/compare-bonsai-fragment-context.js` сохраняет запросы и ответы в отдельный каталог `reports/bonsai-context-runs/<время-прогона>`, читает рабочую базу только для чтения и не создаёт кандидатов. Температура 0, seed 42, лимит 2048 токенов, thinking отключается только для эксперимента. Настройки рабочего подключения не изменяются.

Вставка: запрос явно передаёт неизменяемые `before` и `after` и позицию между ними. Шаблон написания целой главы для вставки не применяется. Запрещается повторять соседнее действие другими словами или заранее показывать результат действия из `after`; задача, уже описанная в правом абзаце, трактуется как запрос на недостающую подготовку/реакцию перед ним. Сборка `before + вставка + after` проверяется отдельным запросом к выбранной модели. Замечания принимаются только с точными цитатами вставки и соседнего текста. При REVISE выполняется одна корректировка и повторная проверка; устойчивый повтор или незавершённая проверка не выдаются как готовая вставка. Подготовка к действию и взгляд другого участника не считаются повтором самого действия. Результат остаётся кандидатом для проверки автором; это инструкция модели, а не автоматическая гарантия семантической корректности. Реальные проверки: `node scripts/verify-bonsai-insertion.js`, отчёты в `reports/bonsai-insertion-fix/<время-прогона>`.
